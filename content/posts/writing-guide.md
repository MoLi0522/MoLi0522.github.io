## 一篇文件，就是一篇文章

所有文章都保存在仓库的 `content/posts/` 目录。你可以在 GitHub 网页里直接创建或编辑文件，也可以在电脑上用喜欢的编辑器写作。

下面是一篇文章的最小模板：

```markdown
+++
title = "我的第一篇学习笔记"
date = "2026-11-04"
slug = "my-first-note"
summary = "用一两句话说明这篇文章的主要内容。"
tags = ["学习笔记"]
demo = false
+++

## 今天学到了什么

在这里写正文。

## 还有哪些疑问

把问题也留下来。
```

`slug` 是文章网址的一部分，请使用小写英文字母、数字和短横线，并确保每篇文章都不相同。`demo = false` 会去掉初始示例标记。

## 支持的写作格式

本站内置轻量 Markdown 解析器，支持二级至四级标题、段落、**加粗**、*斜体*、行内代码、链接、列表、引用和围栏代码块。文章目录会自动从标题中生成。

- 标题先说明问题，再展开过程。
- 代码尽量给出必要的上下文。
- 引用资料时，附上原始链接。
- 结尾可以写下尚未解决的问题。

> 这不是完整的 CommonMark 解析器。复杂表格、嵌套列表和原始 HTML 不在支持范围内；简洁的排版更适合当前站点。

## 发布新文章

如果使用推荐的 GitHub Actions 部署方式，修改并提交文章后，网站会自动重新构建和发布。

本地预览前运行：

```bash
python site.py build
python site.py serve
```

然后打开终端提示的本地地址。修改内容后，需要再次运行构建命令并刷新页面。

## 修改个人资料

姓名、个人介绍、GitHub 账号、教育经历和项目列表集中保存在 `content/profile.json`。更新后重新构建即可。
